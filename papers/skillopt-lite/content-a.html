SkillOpt-Lite 的核心不是一个更聪明的“元优化器”，而是把 Agent 的失败轨迹变成可浏览文件，让编码 Agent 像调试程序一样寻找共性问题，只提交最小文本补丁，并用独立验证集决定保留还是回滚。

02 / 闭环机制

删掉“优化器”，保留最小闭环

原 SkillOpt 有批内合并、文本学习率、拒绝编辑缓存、跨 epoch 慢更新等结构；Lite 版把这些显式机制移除，把“如何看轨迹、如何归因、如何改文档”交给编码 Agent。剩下的刚性约束只有：证据共识、最小补丁、独立验证、可回滚。

较重的元优化框架

SkillOpt

  • 批级候选合并
  • 文本化学习率调度
  • 拒绝编辑缓冲区
  • epoch 级慢更新
⇢
最小充分闭环

SkillOpt-Lite

  • 一条轨迹一个文件
  • Agent 自主浏览与聚类
  • 只改多条证据支持的模式
  • val 退化就回滚
1

轨迹落盘

当前 skill 在 train batch 上运行；每个成功/失败 episode 单独保存，保留输入、工具调用、输出与判分原因。

filesystem staging
2

按症状探索

Agent 先看文件名与首行，按错误症状聚类，再读每簇代表样本；目标不是读完，而是覆盖不同故障模式。

实现提示词
3

共识 + 最小补丁

只处理至少两条轨迹共同支持的模式；不硬编码任务值，不重复已有规则，优先小幅强化而非重写。

consensus mining
4

独立验证门控

候选 skill 在完整 val 上评估；改善则接受，退化则回滚，噪声区间保持不动；test 只在结束时评一次。

validation gate
Cluster first, sample second：先覆盖症状簇，再增加阅读量。
Common patterns only：单样本边角案例不进入 skill。
Smallest patch：官方示例每轮最多 4 处编辑，避免大改引发回归。
Fresh rollout：每轮换 train 子样本；拒绝后也重新生成，使轨迹始终匹配磁盘上的版本。
Dead band：示例门控用 ±0.01 噪声带，微小波动不更新历史最优。
Test sealed：循环内绝不窥看 test，最终恢复 best snapshot 后一次性报告。
03 / 理论视角

它把 Skill 优化看成“语义零阶优化”

模型 M 与 Harness H 固定，只有文本技能 s 可改；奖励来自黑盒执行，因此没有梯度。论文借用 Zeroth-Order Optimization 的语言解释闭环，但关键差异在于：轨迹不是一个标量，而是可读、可归因的语义证据。

s* = arg maxs Ez ~ D [ R( H(M, z, s) ) ]
// 固定模型与执行器，仅通过候选文本的运行结果比较优劣
经典零阶优化

盲扰动 → 看标量反馈

在连续空间里通过随机方向和函数值差估计优化方向。它依赖局部平滑性，通常不知道一次失败“为什么失败”。

SkillOpt-Lite

读轨迹 → 形成语义方向

失败轨迹直接暴露格式陷阱、工具误用、步骤遗漏或恢复策略缺口。编码 Agent 据此提出可解释补丁，接近软件调试与编译优化。

PAC / 稳定性直觉

共识是一种正则化

只接受跨多条轨迹重复出现的模式，相当于抑制对单个训练样本的记忆；独立 val 门控进一步阻断训练反馈自我强化。

工程含义

把可塑性与选择分离

LLM 可以自由提出语义修改，但是否进入生产版本由稳定、机械、可审计的外部评价器决定。

⚠
不要把理论包装误读为收敛定理。论文明确承认文本域没有自然的平滑流形；这里的 ZO/PAC 主要是设计解释与稳定性直觉。正文没有给出收敛率、泛化界数值或统计显著性检验。

05 / HarnessOpt

从改说明书，升级到改执行系统

如果失败不是“策略没写清”，而是上下文预览太窄、代码提取规则错误、工具缺失、循环卡死或重试策略不合适，那么继续改 skill 文本只是在错误层级上优化。HarnessOpt 把可编辑面扩大到 Agent 代码。

Harness 代码

工具 / 记忆 / 上下文 / 循环 / 超时 / 解析

分层诊断原则：“不知道怎么做”多半改 skill；“做法被执行环境卡住”多半改 harness；“根本没有能力”才需要换模型或训练。

Round 0 更谨慎

先全量扫描，再让人批准

官方实现先跑完整 train，形成失败分类，从工具、提示上下文、循环策略、代码生成形态、记忆五个视角提出设计；首个结构改动需人工批准。

可修改面必须受控

Allowlist + Smoke Test

只允许修改指定 Harness 文件；触碰 skill 或评估器即拒绝。完整 val 前先用 5 个任务做编译与冒烟测试，避免昂贵长跑被语法错误浪费。

必须可逆

Git 标签 + 硬回滚

每轮保存 before tag，验证退化就 git reset --hard。这比复制单个文件更适合多文件 Harness 变更，也更容易审计。
