06 / 证据审查

哪些可以相信，哪些仍是开放问题？

下面把论文主张按证据强度拆开。核心方法与广泛分数提升有直接实验支撑；“更快、更便宜、更普适”的强版本结论还需要成本归一化、重复实验与消融。

证据较强

实验直接支持

  • 5 模型 × 6 基准的广覆盖比较。
  • 23/30 单元格超过 SkillOpt。
  • 代码实现与论文的文件探索、共识、小补丁、val 回滚一致。
  • HarnessOpt 在 SpreadsheetBench 上对所有四个模型进一步提升。
有支持但需谨慎

趋势性结论

  • 前 2–3 步更快达到高分，曲线支持“更快收敛”。
  • 小模型 + 好 Harness 可超过大模型 + 弱 Harness。
  • 语义文件探索可能优于显式反馈压缩。
  • 结果暗示复杂度本身会成为优化瓶颈。
尚未充分证明

开放问题

  • 没有多随机种子、置信区间或显著性检验。
  • 没有逐组件消融：文件系统、共识、最小补丁、门控各贡献多少？
  • 没有按 token、调用次数、费用与墙钟时间统一比较。
  • HarnessOpt 只在 SpreadsheetBench 系统评估。
01
预算并非完全同构。
SkillOpt 上限为 4 epochs / 10 batches，Lite 为恰好 10 batches；没有列出实际调用量与上下文 token。
02
验证集可能成为新过拟合面。
每轮都用同一 val 门控，长期迭代会逐渐针对 val 选择；最好使用轮换验证、嵌套验证或保留第二道审计集。
03
数据拆分有调整。
LiveMath 与 OfficeQA 从 2:1:7 改为 2:2:6；OfficeQA 因在线搜索 API 不可用而离线运行，跨论文比较需谨慎。
04
负例不能忽略。
Lite 在 nano 的 SearchQA / OfficeQA、mini 的 OfficeQA、GPT-5.4 的 SearchQA 上落后 SkillOpt，最大回退 2.9 个百分点。
05
理论更像解释框架。
ZO/PAC 提供合理设计直觉，但没有给出文本空间的严格优化几何、收敛保证或泛化界。
06
工程成熟度仍在推进。
论文称其打包为 Copilot 工作流；仓库可直接使用 prompt command，但 agent-agnostic runner、Codex/Claude 插件仍列在 roadmap。
07 / 落地模板

把论文变成可执行工程约束

真正可迁移的不是某个 prompt，而是“提案自由、选择保守、测试封闭、版本可逆”的控制结构。下面是一个更适合生产与研究的增强版最小循环。

baseline = eval(skill, val)
best = snapshot(skill, baseline)

for round in rounds:
    traces = rollout(skill, fresh_train_batch)
    clusters = group_by_symptom(traces)
    evidence = consensus(clusters, support >= 2)
    candidate = minimal_patch(skill, evidence)

    if touches_denylist(candidate): rollback()
    if not smoke_test(candidate): rollback()

    score = eval(candidate, val)
    skill = accept(candidate) if score > baseline + δ \
            else rollback()
    best = max(best, skill)

# test 在循环结束后只运行一次
report(eval(best, test))

研究版必须补的三件事

至少 3 个随机种子；同时报告均值、方差与置信区间；做组件消融和成本归一化，避免只比较最高分。

生产版必须补的三件事

文件 allowlist / denylist；静态检查与小批 smoke；快照、差异、判分、回滚原因全部入审计日志。

更稳健的验证策略

主 val 做每轮门控，shadow-val 定期审计，test 封存；迭代很多时轮换 val 子集或使用 nested validation。

适合使用

判分稳定；失败轨迹可读；错误模式重复；val 成本可接受；修改可回滚；任务分布相对稳定。

不宜直接使用

奖励极噪声或稀疏；任务持续漂移；验证一次非常昂贵；安全关键系统没有人工门；轨迹含敏感数据且无法隔离。

08 / 研究定位

它位于 Skill 优化与 Harness 工程的交叉点

SkillOpt-Lite 不是孤立工作。它一边继承 SkillOpt 的 held-out gate，一边靠近 Meta-Harness 与 AHE 的“文件化、可观察、可回滚”工程路线；与 Trace2Skill 相比，它更强调减少中间汇总结构。
