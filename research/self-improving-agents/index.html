01 · Verdict

先给结论

这是一篇“建立语言和边界”的综述，而不是证明智能体会无限递归进化的实验论文。

它把 Agent 看成一个可更新的系统：基础模型 θ 决定内在能力，脚手架 Σ 决定如何调用能力；自我改进就是 Agent 依据自身运行经验，修改二者之一，并让变化跨任务、跨回合持续存在。

最强贡献

用统一的 θ / Σ 坐标系，把微调、提示优化、记忆、工具学习、工作流搜索放在同一张图里。

最实用洞察

区分瞬时执行状态 X与持久配置更新 A，避免把长思维链、上下文内反思误称为自我改进。

最大缺口

文献覆盖很大，但检索、纳排、编码一致性与定量综合不够透明，因此更像高质量领域地图，而非严格可复现的系统综述。

02 · First principles

统一形式化

把“Agent 变聪明了”拆成可观测变量，才能判断它究竟是在计算、记忆，还是学习。

Aₜ = (θₜ, Σₜ)
Σₜ = (pₜ, mₜ, Tₜ, gₜ)

Aₜ₊₁ = U(A₁:ₜ, E(πθₜ,Σₜ; Cₜ))

θ：模型参数；p：提示/策略；m：记忆；T：工具；g：控制流或多智能体拓扑；U：更新算子；E：反馈/评估。

持久性的判据

给定同类任务，移除本回合临时上下文后，新配置是否仍系统性改变未来行为？

是：写入长期记忆、修改提示、添加工具、重排工作流、更新权重。
否：单次链式思考、临时草稿、当前轨迹中的自我反思。

结构性观察

脚手架改进 166 篇，明显多于模型改进 73 篇。原因不是权重更新不重要，而是脚手架更便宜、可逆、可在线试验，也更适配闭源模型。

其中长期记忆与工具学习最拥挤；完整脚手架搜索数量少，却最接近“系统自己设计系统”的强版本。

04 · Mechanism

真正的共同结构

不论方法名叫什么，几乎都可还原成四个部件。区别只在每个部件由谁实现、是否可验证、更新是否可回滚。

提出候选更新
新提示、新记忆、新工具、新工作流或新参数。
在任务分布上试运行
获得成功率、质量、代价、延迟和安全轨迹。
独立评价与归因
判断增益来自真正泛化，还是评测投机、数据泄漏或资源膨胀。
接受、回滚或蒸馏
将可靠更新持久化，不可靠更新隔离。
05 · Evaluation

不要只看终点分数

自我改进是一个动态过程。只报告“迭代后提升多少”会掩盖成本、波动、遗忘、评测泄漏和安全回退。

最小可接受评测协议

全轨迹同预算留出任务成本回归安全

  • 画出随迭代变化的曲线，不只报最佳点。
  • 将 token、调用次数、训练算力、延迟、人类监督统一计入预算。
  • 更新生成集与最终验收集隔离，避免“自己出题自己判卷”。
  • 报告失败率、方差、灾难性遗忘与任务外迁移。
  • 对 LLM-as-a-Judge 使用独立模型或可执行验证器，防止奖励黑客。
06 · Safety

改进器本身也要被治理

一旦 Agent 能修改提示、记忆、工具甚至自身代码，安全边界不再是静态规则，而是一个持续接受更新的系统。

提议者 ≠ 接受者

生成更新的 Agent 不应拥有直接写入生产配置的最终权限。将“想法”与“发布”分权。

可逆优先

先在分支、沙箱和影子流量中试验；每次更新都有版本、证据、回滚点和影响范围。

权重更新重审

模型参数变化会让旧的行为边界和红队结论失效，必须触发更高等级的重新评估。

关键风险：自动评审器也属于攻击面。优化器可以学习“让评审器满意”，却不一定真正完成任务。因此 critic / judge 应被当作受治理基础设施，而不是一句提示词。
07 · Critical reading

这篇论文哪里强，哪里弱

下面区分作者明确论述、由论文结构可推出的工程含义，以及本解读的批判性判断。

值得引用的四点

  1. 系统边界清楚：把模型与脚手架视为共同决定行为的 Agent 配置。
  2. 持久更新判据：把自我改进从 test-time compute 中剥离出来。
  3. 跨方法统一：参数学习、记忆、工具、工作流不再是孤岛。
  4. 动态评测意识：强调资源约束、回归、安全和长期演化。

需要保留意见的四点

  1. 综述流程：未见完整数据库、查询式、纳排流程和编码者一致性报告。
  2. 分类重叠：记忆、工具、提示和完整脚手架在真实系统中常同时更新。
  3. 定义偏宽：只要更新由自身轨迹触发，就可能被纳入，自治程度差异很大。
  4. 证据层级：以叙述性归纳为主，不是统一基准上的定量 meta-analysis。

  1. 更新对象是否有清晰版本号？
  2. 谁能提出更新，谁能批准更新？
  3. 验收集是否与改进回路隔离？
  4. 同等预算下真的更好吗？
  5. 失败是否自动回滚？
